# 울림 전문가·상담 MVP

회원 가입부터 전문가 경력 등록·운영자 승인·공개 프로필·상담 신청·수락·일정 확정·결과 기록까지 연결되는 독립 실행 웹사이트입니다. 기존 Vercel 사이트는 교체하지 않았으며 기존 취약 API를 사용하지 않습니다.

## 실행
Node.js 24 이상. 외부 npm 의존성 없음.

```sh
npm test
npm start
```

기본 주소 http://127.0.0.1:8766

- `/join?role=expert`: 전문가 가입
- `/expert/register`: 경력·상담 주제·선택 PDF 등록, 초안 저장·검토 요청
- `/experts`: 승인된 실제 전문가 검색·산업/직무 필터
- `/join`, `/login`, `/my`: 상담 고객 가입·로그인·상담 관리
- `/admin`: 운영자 로그인 및 일반 문의 관리
- `/admin/platform`: 전문가 승인·보완 요청, 상담 현황·고객 동의 후 재매칭

## 전문가 모집과 실제 운영
1. 운영자가 지인에게 사업 모델·참여 조건을 설명하고 전문가 가입 주소를 전달합니다.
2. 전문가가 직접 가입한 뒤 경력과 상담 가능한 질문을 입력합니다. PDF는 선택 사항, 최대 3MB입니다.
3. 소속명 공개는 기본 해제되어 있습니다. PDF 원본은 공개되지 않습니다.
4. 운영자가 별도 연락으로 본인·경력·참여 의사·상담 범위·겸업·운영 조건을 확인하고 승인합니다.
5. 승인한 프로필만 공개됩니다. 승인 후 경력 수정·PDF 교체 시 재검토합니다.
6. 고객이 가입해 해당 전문가에게 신청합니다. 전문가는 수락/거절하고 시간·접속 방법을 제안합니다. 고객이 확정한 뒤 실제 상담을 진행합니다.
7. 상담 시간이 지난 뒤 전문가가 결과와 다음 행동을 기록합니다. 당사자는 내 상담에서 확인합니다.

실제 전문가는 아직 등록되어 있지 않습니다. 기본 공개 목록은 비어 있고 가상 전문가를 기본 데이터로 넣지 않습니다. 전문가 10~20명 등록에 인원 제한은 없습니다. 가격은 전문가별 무료 파일럿/개별 협의/입력 금액으로 표시되며 결제 기능은 없습니다. 상담은 별도 화상 도구나 대면으로 진행하며 플랫폼이 영상 연결을 제공하지 않습니다.

## 로그인과 데이터
회원 비밀번호는 scrypt 해시로 저장합니다. 회원/운영자 세션은 분리하고 HttpOnly·SameSite 쿠키, 운영 HTTPS에서는 Secure 쿠키를 사용합니다. 쓰기 요청은 Origin과 세션별 CSRF를 검사합니다. 공개 API는 승인 프로필의 허용 필드만 반환하며 이메일·비공개 소속·이력서 원본을 제외합니다. 상담은 당사자와 운영자만 열람합니다. 동시 수정은 버전 충돌로 차단합니다.

자동 이메일 소유권 인증·접수 알림·비밀번호 재설정 메일은 아직 없습니다. 운영자가 지인/별도 연락으로 본인과 참여 의사를 확인해야 합니다. 회원은 로그인 후 비밀번호를 변경할 수 있습니다. 비밀번호를 잊었거나 탈퇴/개인정보 삭제를 원하면 운영자가 본인 확인 후 처리해야 합니다. UI 안내만으로 본인 확인이 완료된 것으로 간주하지 마세요.

SQLite 데이터는 DATA_DIR에 저장합니다. 로컬에서는 최초 실행 시 관리자 비밀번호 파일 `admin-password.txt`를 권한 600으로 만듭니다. 비밀번호를 로그에 출력하거나 Git·압축 파일에 넣지 않습니다. 관리자 세션은 서버 재시작 시 만료되고 회원 세션은 최대 8시간입니다.

이번 채팅에서는 실제 사용 데이터 디렉터리를 `work/ulim-runtime`, 격리된 가상 테스트 디렉터리를 `work/ulim-platform-qa`로 분리했습니다. 현재 실제 사용 DB에는 이전 단계의 가상 일반 문의 1건만 있고 실제 회원/전문가는 없습니다.

종료 일반 문의는 90일, 종료 상담은 365일 후 관련 이력과 함께 정리합니다. 상담 정리는 요청이 들어올 때 시간 단위로 실행됩니다. 회원/프로필/이력서는 계정 운영 기간 보관하며 삭제 요청은 수동 처리합니다. 운영 DB와 백업은 접근 제한된 저장소에 보관해야 합니다.

## 공개 배포
현재 주소는 집 Mac의 로컬 확인용이며 지인에게 외부 모집 주소로 전달할 수 없습니다. 기존 GitHub에 푸시하거나 Vercel 사이트에 배포하지 않았습니다. 실제 모집을 시작하려면 HTTPS 도메인과 SQLite 영속 볼륨을 제공하는 단일 서버에 배포해야 합니다. 현재 서버를 그대로 일회성 Vercel 서버리스 함수로 배포하지 마세요.

```text
NODE_ENV=production
PUBLIC_ORIGIN=https://실제-서비스-도메인
ADMIN_PASSWORD=비밀저장소에-설정한-12자-이상-비밀번호
HOST=0.0.0.0
PORT=8766
DATA_DIR=/data/ulim
```

```sh
docker build -t ulim-mvp .
docker run --env-file /보안경로/ulim.env -v /영속경로/ulim:/data -p 8766:8766 ulim-mvp
```

볼륨은 컨테이너 node 사용자에게 읽기/쓰기 권한이 있어야 합니다. HTTPS 프록시·백업·운영 담당자 연락처·개인정보처리방침을 실제 환경에 맞춰 설정하고 `/api/health`를 확인하세요. 요청 제한은 단일 인스턴스 메모리 기준이며 프록시 환경에 맞는 호스팅측 제한도 필요합니다. 임의의 X-Forwarded-For를 신뢰하지 않습니다.

## 검증과 남은 범위
`npm test`: 문의 저장/중복/보관, 가입·역할·세션, 전문가 승인과 비공개 정보, PDF 접근 제한, 상담 수락·일정 확정·결과 기록, 다른 회원의 접근 차단, 재매칭을 검증합니다. 브라우저에서도 격리된 가상 전문가로 가입→경력 제출→운영자 승인→공개 목록 반영을 확인했습니다.

자동 이메일·온라인 결제·화상 상담·기업 채용 계약/정산·기업 인재 DB는 제공하지 않습니다. 전문가는 실제로 모집해야 하며 자동 매칭 알고리즘 대신 고객 선택과 운영자 수동 재매칭을 제공합니다.


## 배포 준비 보완 — 2026-10-22
Docker는 root로 영속 볼륨의 `/data/ulim` 폴더만 초기화한 뒤 `su-exec`로 node 사용자에게 권한을 낮춰 서버를 실행합니다. 볼륨은 `/data`에 마운트하고 `DATA_DIR=/data/ulim`을 사용하세요. 기존 `/data/ulim.sqlite`를 사용 중인 운영 환경이 있다면 별도 데이터 이동이 필요하므로 경로만 바꾸지 마세요. 이번 새 서비스는 빈 DB에서 시작합니다. Docker 실행 환경이 없어 실제 이미지 빌드·볼륨 연결 검증은 아직 하지 않았습니다.

운영 환경은 절대 경로 DATA_DIR과 유효한 HTTPS PUBLIC_ORIGIN이 없으면 시작하지 않습니다. `.env.example`은 값 입력 형식이며 실제 비밀번호가 없습니다. `.env.*`와 SQLite 파일은 소스/이미지에서 제외합니다.

수동 백업: `node scripts/backup.mjs /data/ulim/ulim.sqlite /보호된-백업경로/새이름.sqlite`. 실행 중 WAL을 포함한 일관된 SQLite 스냅샷을 만들고 무결성을 검사합니다. 기존 백업은 덮어쓰지 않습니다. 같은 볼륨의 사본만으로 장애 복구가 보장되지는 않으므로 별도 보호 저장소로 옮겨 보관하세요. 복원은 DEPLOYMENT.md를 참고하세요.

통합 테스트는 21개이며 운영 설정 거절, WAL 스냅샷·복원, 재시작 후 전문가 계정·경력·PDF 보존까지 확인했습니다. 실제 Railway 영속 볼륨과 백업 기능 검증은 호스팅 복구 후 남아 있습니다.


## 관리자 수동 백업 — 2026-10-23
운영자 로그인 후 `/admin/backup`에서 개인정보 포함 확인을 선택하고 백업을 다운로드합니다. 회원·비공개 PDF·상담·문의가 포함되며 관리자/회원 로그인 세션은 제외됩니다. 서버 임시 파일은 전송 완료·실패 후 정리됩니다. 파일은 암호화되지 않으므로 서버와 분리된 암호화 보호 저장소에 보관하고, 삭제 요청 시 사본 보관 정책도 적용해야 합니다. 자동 백업을 설정하는 기능은 아닙니다. 백업은 본 서비스와 같은 신뢰 경계의 운영자만 다운로드하며 운영 중 잦은 요청은 제한합니다. 23개 테스트와 격리 브라우저에서 확인했습니다. 실제 운영 백업 파일의 다운로드·보관·복원은 사용자가 확인해야 합니다.
