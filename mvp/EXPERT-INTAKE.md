# 초기 전문가 모집: 이력서로 참여 신청

## 지인에게 안내할 주소

https://glistening-unity-production-eeb7.up.railway.app/expert/register

전문가 계정으로 가입·로그인한 뒤 이름·안내 이메일을 확인하고 PDF 이력서를 제출한다. 전화번호와 희망 상담 주제는 선택이다. 계정은 원본 이력서와 신청 상태, 소개 초안을 본인만 확인하는 데 사용한다. PDF는 최대 3MB이며 Word/HWP는 PDF로 변환해야 한다.

이력서 제출로 **참여 신청 접수**가 완료된다. 즉시 공개 전문가로 등록되거나 상담이 배정되는 것은 아니다. AI API는 필요하지 않으며, 이 흐름은 이력서를 외부 AI에 보내지 않는다.

## 운영 순서

1. `/admin`에서 운영자 로그인 → `/admin/intakes`에서 신청·접수번호·비공개 PDF 확인.
2. 이력서와 본인 연락으로 확인된 경력·상담 가능 주제를 정리한 후 **소개 저장·본인 확인 대기로** 선택.
3. 운영자가 가입 이메일/선택 연락처로 직접 안내. 자동 이메일 발송은 없다. 확인 주소는 `/expert/register`이며, 신청자 자신의 계정으로 로그인해야 한다.
4. 전문가가 소개·경력·공개 범위·상담 조건을 확인·수정하고 검토 신청.
5. `/admin/platform`에서 참여 조건을 최종 확인한 후 승인·공개.

운영자 초안 작성 또는 수정은 `awaiting_expert` 상태로만 저장된다. 승인 API는 전문가가 현재 소개 내용에 동의한 기록을 대조한다. 운영자 재수정·이력서 재접수 시 확인 상태를 무효화한다. 단순히 관리자가 상태를 검토 대기로 바꾸어도 본인 확인을 우회할 수 없다.

기존 직접 작성 방식은 `/expert/register?edit=1`에 유지한다. 기존 프로필 보유자는 해당 화면으로 안내한다. 공개·상담 이력이 없는 신청은 본인이 철회할 수 있고 PDF·소개·선택 연락처·희망 주제를 삭제한다. 접수번호·계정 연결·동의 기록은 보존한다. 공개·상담 이력이 있는 경우 운영자에게 연락해 처리한다.

## 구현과 검증

`expert_intakes` 테이블을 추가하는 비파괴 초기화다. 기존 회원·프로필·PDF·상담 데이터는 이전하지 않는다. 서버 Dockerfile에 새 모듈을 포함한다. 운영 환경은 기존 단일 인스턴스·영속 볼륨 설정을 유지한다.

2026-11-04~05: 접수부터 본인 확인·승인까지, 인증·CSRF·역할·파일 형식·동의·중복 제출/버전 충돌·타인 접근·재수정·철회/재신청 테스트를 추가했다. 관련 서버 검사 26개가 통과했고, 격리한 로컬 화면에서 PDF 접수→운영자 초안→본인 수정·검토 신청을 확인했다. 실제 사람의 이력서를 테스트에 사용하지 않았다.

기존 전체 테스트의 백업 권한/정리 관련 Windows 실패는 이 기능과 별도로 기록되어 있다(`RESUME-AUTOFILL.md`). 배포 후 건강 상태와 새 페이지·엔드포인트를 별도로 확인한다.
